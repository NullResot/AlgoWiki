# AlgoWiki 发布与更新操作手册

适用对象：测试发布、正式发布和故障回滚的维护者。

## 1. 发布原则

- 功能先进入 `develop`，再通过 Pull Request 依次晋级到 `test` 和 `main`；
- 测试与生产运行同一个不可变镜像摘要；
- 生产部署必须由 GitHub `production` Environment 的人工审批解锁；
- 真实密钥只存在于服务器环境文件或 GitHub Environment secrets；
- 数据库变更采用可向后兼容的 expand/contract 方式。

## 2. 发布到测试环境

1. 在 GitHub 创建 `develop -> test` Pull Request。
2. 等待 `Promotion policy`、`Backend tests`、`Frontend tests`、`Container configuration` 和 `Container build` 全部成功。
3. 合并 Pull Request。不要在本机直接 push `test`。
4. `Publish immutable test image` 会发布带完整 commit 标签的 GHCR 镜像。
5. `Authorize test release` 把本次构建输出的精确镜像摘要写入同一 commit 的 GitHub `test` Environment deployment；成功后服务器拉取器在约三分钟内读取该授权摘要、部署到 `test.algowiki.cn` 并执行健康检查。服务器不会重新解析可移动镜像标签。
6. 按 [分支与测试环境部署](./分支与测试环境部署.md) 的验收清单完成业务验收。

## 3. 发布到生产环境

1. 确认测试验收记录与待发布 `test` commit 一致。
2. 在 GitHub 创建 `test -> main` Pull Request。
3. 等待所有必需检查成功并合并。
4. 流水线从已合并 Pull Request 元数据验证 `main` 来源和源码树；生产服务器按该 `test` commit 读取成功验收时记录的同一镜像摘要。
5. `Authorize production deployment` 会停在 GitHub Environment 审批门前。
6. 发布负责人核对 commit、测试结果和变更窗口后，在 GitHub Actions 页面批准该 job。
7. 部署命令先备份生产数据库，再迁移、切换容器并验证内外网健康检查。

审批只解锁当前这一次部署，不应关闭 Environment 的长期保护规则。

## 4. 发布后验证

至少确认：

```bash
curl -fsS https://www.algowiki.cn/api/health/
```

再人工检查首页、登录、个人中心、Wiki、动态、审核台、管理后台和图片上传。服务器上可只读检查：

```bash
docker compose --project-directory /srv/algowiki \
  --env-file /srv/algowiki/deploy/.env.production \
  -f /srv/algowiki/docker-compose.server.yml \
  -p algowiki ps
```

成功部署记录保存在 `/var/lib/algowiki/deployments/<environment>/last-success`，该目录仅 root 可读。

## 5. 失败与回滚语义

自动部署在服务切换失败时会恢复上一个 `APP_IMAGE` 并重新等待容器健康，但不会自动反向执行数据库迁移。这一点是故意的：自动 reverse migration 可能造成不可恢复的数据损失。

如果失败发生在迁移之后：

1. 保持上一个应用镜像运行；
2. 保存 Actions 与服务器日志；
3. 判断新 schema 是否仍与旧应用兼容；
4. 只有在确认数据影响和恢复文件后，才决定前向修复或人工数据库恢复。

生产备份默认写入 `/var/backups/algowiki/db`，包含 SHA-256 校验文件。恢复前必须停止写入、再次备份当前库，并先在隔离环境验证。

## 6. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| PR 无法合并 | 分支来源、必需检查、ruleset |
| test 镜像未发布 | 后端/前端/Compose 检查、GHCR 权限 |
| 拉取器未部署 | `systemctl status algowiki-release-poller.timer`、`journalctl -u algowiki-release-poller.service` |
| GitHub 状态无法读取 | 服务器到 `api.github.com:443` 的出站连通性与公开 API 速率限制 |
| 部署包装器失败 | root-owned 包装器、部署日志、环境状态与镜像摘要 |
| revision 或授权摘要不匹配 | `test` Environment deployment 是否属于当前完整 commit，授权 URL 中的 digest 是否与构建输出一致 |
| 生产 job 等待 | 正常的 Environment 人工审批状态 |
| 健康检查失败 | 容器日志、数据库/Redis 连接、Nginx upstream |
| 迁移后回滚 | 不要自动 reverse；按本节评估 schema 兼容性和备份 |
