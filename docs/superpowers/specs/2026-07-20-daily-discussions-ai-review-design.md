# AlgoWiki 每日讨论、全站 AI 审核与脉冲排行榜设计

日期：2026-07-20  
状态：已批准  
负责人：Codex  

## 1. 背景与已确认决策

本次工作解决四个相互关联的问题：

1. test 必须完整继承 main，只允许叠加已经批准的午夜脉冲改动与本次增量。
2. 动态中新增「每日讨论」子页面，归档全部历史话题，并提供知乎式的单问题、多回答结构。
3. 全站公开文字内容必须先通过 AI 审核，审核服务不可用时不得公开，并自动重试。
4. 脉冲排行榜改为服务端分页，支持每页 10、20、50 条，并消除当前行重叠。

用户已经确认：

- 热门讨论投稿通过管理员审核后，排入未来某天的每日讨论。
- AI 审核覆盖全站公开讨论文字，包括动态、动态评论、Wiki 评论、问答、每日讨论回答。
- AI 超时、额度耗尽或配置不可用时，内容保持待审并自动重试，不允许人工绕过后直接公开。
- 历史每日讨论永久开放回答，只有当天首次合格回答获得换签卷。
- 后续产品与技术细节由推荐方案直接决定，不再逐项询问。

## 2. 设计原则

### 2.1 产品原则

- 每日讨论既是当天回访入口，也是长期可检索的算法竞赛观点库。
- 用户必须明确看到内容处于「AI 审核中」「已公开」或「未通过」中的哪一种状态。
- 审核失败时优先保护公开内容安全，不以可用性为由绕过审核。
- 热门话题投稿与日常回答使用不同流程：投稿需要 AI 预审和管理员排期，回答只需要 AI 审核。
- 排行榜分页必须由服务端完成，前端不得一次加载 100 条后伪分页。

### 2.2 视觉论点

- 视觉主题：沿用 AlgoWiki 已有 Modern、Midnight 与黑珍珠主题令牌，不新增孤立皮肤。
- 设计签名：每日讨论使用纵向日期轨道和金色脉冲点，将「每天一个问题」变成可识别的时间序列。
- 内容结构：先展示当天问题和历史索引，再进入单个问题及回答详情，不使用堆叠的同质卡片墙。
- 交互节奏：路由与分页采用 180 至 240ms 的淡入和轻位移，只动画 transform 与 opacity，并遵守 `prefers-reduced-motion`。
- CSS 策略：继续使用 Vue 单文件组件中的 scoped CSS 与现有全局主题变量，不引入 Tailwind、CSS Modules 或 CSS-in-JS。

### 2.3 成熟产品借鉴

- 知乎：一个问题长期承载多份回答，列表强调标题、回答量和内容摘要。
- Stack Overflow：问题归档可按最新与活跃度浏览，标签帮助用户快速定位感兴趣内容。
- Discourse 与 Reddit：不同内容类型进入统一审核队列，并通过状态、类型与优先级筛选。

本项目只吸收信息结构和审核模式，不复制这些产品的视觉皮肤。

## 4. 信息架构与页面

### 4.1 动态页子导航

动态页顶部增加同级子导航：

- 动态广场
- 每日讨论

桌面端使用当前页面内的细线活动指示，移动端使用可横向滚动的标签栏。两个入口共享顶栏和主题，不复制全站导航。

### 4.2 每日讨论归档

路由：`/moments/discussions`

桌面布局：

- 主列：当天问题、历史讨论列表、搜索和排序。
- 辅助列：今日状态、我的待审回答、提交热门话题入口。
- 历史列表采用日期轨道，不使用相同尺寸的卡片网格。

每条历史讨论显示：

- 日期与来源标记。
- 标题和两行摘要。
- 标签、公开回答数、最近活跃时间。
- 用户是否在当天参与，以及奖励是否已经领取。

筛选能力：

- 关键词搜索。
- 最新发布。
- 最近活跃。
- 我参与的。

### 4.3 讨论详情

路由：`/moments/discussions/:date`

详情页包含：

- 问题标题、正文、日期、来源和标签。
- 回答数量以及最新、最早两种排序。
- 支持 Markdown 的长回答编辑区，上限沿用现有回答上限 20,000 字符。
- 回答提交后的本地状态条，明确显示 AI 审核中。
- 作者可以看到自己的待审或驳回答案，其他用户只能看到已公开答案。

历史问题永久可回答。换签卷奖励只在业务日期等于讨论日期，并且是该用户当天首次通过审核的有效回答时发放。

### 4.4 热门话题投稿

入口：每日讨论归档页右侧辅助列，移动端位于当天问题之后。

投稿字段：

- 话题标题。
- 背景说明。
- 最多 5 个算法竞赛相关标签。

流程：

1. 用户提交后先进入 AI 预审。
2. AI 判定安全后进入管理员话题队列。
3. 管理员查看内容、投稿人和 AI 摘要，选择一个未被占用的未来日期。
4. 批准后创建对应日期的草稿版 `PulseDailyEdition`，来源为 `hot`。
5. 北京时间 00:00 发布该日期版本。

管理员可以驳回并填写原因。已占用日期不可重复排期。

## 5. 数据模型

### 5.1 复用模型

- `PulseDailyEdition` 继续一对一关联 `Question`。
- 每日讨论回答继续使用 `Answer`。
- 现有动态、评论、问答与 AI 审核记录继续复用。

### 5.2 新增 `PulseTopicProposal`

建议字段：

- `proposer`
- `title`
- `content_md`
- `tags`，JSON 数组，最多 5 项
- `status`：`ai_pending`、`admin_pending`、`scheduled`、`rejected`
- `ai_record`
- `reviewer`
- `review_note`
- `reviewed_at`
- `scheduled_date`
- `edition`
- `created_at`、`updated_at`

约束：

- `scheduled_date` 与 `edition.date` 必须一致。
- 同一提案最多创建一个每日版本。
- 只有 `admin_pending` 状态允许管理员排期。

### 5.3 AI 重试字段

在审核记录中补充：

- `attempt_count`
- `next_retry_at`
- `last_attempt_at`
- `retry_state`：`queued`、`processing`、`finished`

使用数据库条件更新领取任务，避免多个工作进程重复审核同一内容。

## 6. AI 审核状态机

### 6.1 发布规则

所有用户公开文字创建或编辑后先保存为待审：

- AI 安全：发布，并记录审核模型、耗时和摘要。
- AI 不安全：隐藏或驳回，向作者显示原因。
- AI 可疑：保持待审，不允许管理员直接公开；用户修改后重新送审。
- AI 不可用：保持待审，进入自动重试队列。

管理员可以删除、驳回或要求修改，但不能绕过 AI 安全结论直接发布。

### 6.2 自动重试

- 提供独立审核工作进程，每次领取有限数量的到期记录。
- 退避间隔为 1、5、15、60 分钟，之后每 60 分钟重试。
- 配置未启用或 API Key 缺失时不发送请求，但记录保持 queued，并按小时重新检查。
- 用户编辑内容时废弃旧审核结果，生成新记录，避免旧结果覆盖新内容。
- 成功或明确拒绝后停止重试。

### 6.3 覆盖范围

本次强制覆盖：

- `ArticleComment`
- `Question`
- `Answer`，包括每日讨论回答
- `Moment`
- `MomentComment`
- `PulseTopicProposal`

投票、点赞、签到、Codeforces 提交和管理员生成的系统内容不属于用户言论。

## 7. API 设计

### 7.1 每日讨论

- `GET /api/pulse/discussions/`
  - 参数：`page`、`page_size`、`sort`、`q`、`mine`
  - 返回：`count`、`page`、`page_size`、`total_pages`、`results`
- `GET /api/pulse/discussions/:date/`
- `GET /api/pulse/discussions/:date/answers/`
  - 参数：`page`、`page_size`、`sort`
- `POST /api/pulse/discussions/:date/answers/`
- `POST /api/pulse/topic-proposals/`
- `GET /api/pulse/topic-proposals/mine/`

### 7.2 管理员话题队列

- `GET /api/pulse/admin/topic-proposals/`
- `POST /api/pulse/admin/topic-proposals/:id/schedule/`
- `POST /api/pulse/admin/topic-proposals/:id/reject/`

排期接口必须在事务中锁定目标日期，避免重复占用。

### 7.3 排行榜

- `GET /api/pulse/rankings/`
  - 保留学校和 Rating 范围筛选。
  - 新增 `page` 与 `page_size`。
  - `page_size` 仅允许 10、20、50，默认 20。
  - 返回 `count`、`page`、`page_size`、`total_pages`、`results`。

排名数字基于完整筛选集合计算，不因分页从 1 重新开始。连续天数只为当前页用户计算。

## 8. 排行榜界面

- 删除固定 `repeat(5, ...)` 行轨道，行高保持稳定，不再让多条数据占用同一网格行。
- 表头吸顶，姓名与学校分两行，数值列右对齐并使用等宽数字。
- 页面大小选择器放在表格右上方，支持 10、20、50。
- 页码与上一页、下一页放在表格底部。
- 20 与 50 条模式允许表格区域内部纵向滚动，页面本身保持稳定。
- 切换全站、Rating 段、高校时自动回到第 1 页。
- 当前用户行使用低对比度主题色底纹，不改变字号或行高。
- 375px 下隐藏学校次要信息，保留名次、用户名、连续天数和积分。

## 10. 主题、响应式与可访问性

- 只使用现有主题变量表达背景、文字、边线、金色脉冲与状态色。
- 暗色层级通过背景亮度台阶表达，不用黑底黑阴影。
- 中文正文行高保持 1.7 左右，排行榜数值使用 tabular numbers。
- 所有交互目标至少 40px。
- 键盘可以操作子导航、排序、分页和提交表单。
- 375px 与 1280px 作为必测宽度，额外检查 320px 按钮文字。
- 减少动态效果开启时关闭位移，只保留即时状态变化。

## 11. 验收标准

### 分支与部署

- 候选分支包含最新 main 和全部已批准午夜脉冲提交。
- 未批准的 main 文件无差异、无删除。
- test 分支与部署 release SHA 一致。
- main 和正式站点不受影响。

### 每日讨论

- 可以浏览所有已发布日期，查看单个问题与公开回答。
- 历史问题可继续回答，但不会补发当天奖励。
- 当前日期首次通过 AI 的回答只发放一次换签卷。
- 用户能看到自己的待审状态，其他用户看不到待审内容。

### 话题投稿

- 投稿先通过 AI，再进入管理员队列。
- 管理员只能排入未占用的未来日期。
- 00:00 发布后出现在今日脉冲和历史归档中。

### AI 审核

- 列出的所有公开文字入口都不能直接公开未审核内容。
- 服务异常时内容保持待审，并可观察到自动重试。
- 编辑后的内容不会被旧审核结果误发布。

### 排行榜

- 支持 10、20、50 条，服务端返回正确分页元数据。
- 跨页排名连续，筛选后排名正确。
- 桌面与移动端无文字重叠，50 条模式可滚动。

## 12. 非目标

- 本次不增加回答点赞、采纳答案、关注话题或复杂推荐算法。
- 本次不修改正式站点 main。
- 本次不更换 AI 供应商，也不把管理员审核替代为 AI 审核。
- 本次不重做动态广场现有信息流。
