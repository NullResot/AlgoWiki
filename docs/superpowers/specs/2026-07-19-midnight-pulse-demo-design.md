# 午夜脉冲剧场 Demo 设计说明

## 目标

在不改变 AlgoWiki 现有首页主体的前提下，增加一个每天值得回来查看和参与的入口。Demo 用本地模拟数据验证三件事：首次访问是否有仪式感、三项每日内容是否足够清晰、完成后的“算法星图”反馈是否有持续吸引力。

## Demo 边界

- 仅前端交互与 `localStorage` 持久化，不连接 Codeforces、积分、发券、排行榜或问答后端。
- 题目、VP、回答、投票、排行和历史星图均为明确标注的模拟数据。
- 为完整演示两次同模式换签，初始预置一张体验换签卷；首次回答再获得一张。
- 独立路由为 `/pulse-demo`，避免占用未来正式功能的 `/pulse`。
- 工作位于从 `origin/test` 创建的隔离分支 `codex/midnight-pulse-demo`，不修改或部署正式站点。

## 信息架构

### 首页首次访问

每个浏览器自然日第一次访问首页时，在现有导航与首页内容之间展开一张“午夜脉冲”日签。它展示 0/3 完成进度、当天三项事件摘要和进入剧场的主按钮。关闭后当日不再自动展开，现有首页布局与内容保持原样。

### 顶栏入口

顶栏新增紧凑入口：未完成时显示 `今日脉冲 n/3`，全部完成后切换为绿色星标 `今日完成`。它在当天第二次及之后的访问中承担唯一常驻入口，点击前往独立 Demo 页。

### 独立脉冲页

页面提供三个视图：

1. `今夜观测台`：核心交互区，围绕一颗中心算法星组织每日问答、挑战和争议投票。
2. `我的星图`：展示连续参与、每日亮度、补签轨迹和两类连续签到。
3. `脉冲排行`：展示月榜为主、总榜为辅，以及全站、Rating 段、高校三个范围。

移动端内容顺序固定为：中心星 → 问答 → 挑战 → 投票。

## 核心交互

### 每日问答

当天提供一个算法竞赛相关话题。用户可输入一段简短回答并发布；当日首次发布回答后，社区进度完成，并获得一张换签卷。重复点击不重复发券。

### 每日挑战

用户在 A、B 两种模式中二选一：

- A：按绑定 Codeforces Rating + 300 模拟抽取未 AC 题，难度限制在 800–3500，完成后 +1。
- B：按 Rating 段模拟抽取未参加 VP，要求至少完成 n-2 题，最晚到次日 04:00，完成后 +3。

选择模式后当日锁定模式。每种模式可使用换签两次，只在当前模式内切换内容。Demo 的“模拟检测完成”按钮直接改变完成状态和积分。

### 争议投票

当天提供一个算法竞赛争议话题和多个选项。用户只能投一次；投票后显示各选项比例与总票数。

## 视觉语言

- 页面整体采用深色天文观测台氛围，使用暖金作为今日脉冲主色，青蓝表示训练轨道，紫色表示观点信号，绿色表示完成。
- 中央算法星随完成度从暗核变为发光恒星。问答点亮知识核心，挑战点亮外层轨道，投票改变表面纹理。
- 保留 AlgoWiki 现有顶栏、主题变量和圆角体系；首页新增部分使用轻量背景，避免压过用户认可的现有首页。
- 不使用外部图片或新字体依赖，星体、轨道和光晕由 CSS 绘制。

## 状态与持久化

状态按本地日期保存，包含首次访问标记、问答、获得的换签卷、挑战模式、抽签索引、换签次数、挑战完成状态、积分和投票选项。日期变化时自动创建新一天状态；Demo 重置按钮清除本地状态，便于重复验收。

## 可验证标准

- 第一次进入首页自动展示日签；关闭后刷新不再自动展示。
- 顶栏始终可进入 `/pulse-demo`，进度从 0/3 更新到 3/3，并在完成时显示 `今日完成`。
- 回答只发一张换签卷；挑战模式锁定；换签不跨模式且最多两次；A/B 分别加 1/3 分；投票不可重复。
- 重置后恢复 0/3，首页首次访问日签可再次出现。
- `npm run test:pulse-demo` 与 `npm run build` 通过，桌面与移动端核心内容无横向溢出。
