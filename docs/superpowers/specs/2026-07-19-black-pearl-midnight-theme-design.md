# 黑珍珠 Midnight 主题与每日拟真星球设计规格

## 1. 目标与既有规格关系

本规格在以下既有成果上进行视觉升级，不重写已经完成并通过验收的午夜脉冲业务逻辑：

- `2026-07-19-midnight-pulse-production-design.md` 定义的社区问答、Codeforces 绑定、每日挑战、投票、积分、道具、排行榜和管理能力继续有效。
- `2026-07-19-eclipse-observatory-theme-motion-design.md` 定义的临时主题、离开页面恢复原主题、减少动态效果和单屏布局继续有效。
- 本规格替换旧的「日蚀观测台」材质方向，将全站 `Midnight` 主题升级为已经确认的「孔雀金丝」黑珍珠主题，并将脉冲页中央 CSS 算法星替换为每日固定的一颗拟真星球。

本次不修改正式环境，不部署，不推送远端；实现继续位于隔离分支 `codex/midnight-pulse-demo`。

## 2. 已确认的视觉方向

### 2.1 孔雀金丝

黑珍珠不是纯黑表面。主题使用黑、青绿、深蓝、幽紫和银灰构成珠母虹彩，香槟金只用于导航焦点、主要操作、完成状态和精细镶线。视觉贵气来自材质、反射和空间层次，而不是大面积金色描边。

材质参考来自 MIKIMOTO 对黑南洋珍珠多色谱与孔雀色的介绍，以及 TASAKI 对黑珍珠、银色金属和精细珠光的克制表达。只提取色彩、光泽和层级规律，不复制品牌页面布局或素材。

参考：

- https://www.mikimoto.com/jp_en/pearl
- https://www.tasaki-global.com/jewellery/pearl-necklaces/

### 2.2 颜色语义

- 深空底：`#03070B` 至 `#071019`，避免整页纯黑。
- 黑珍珠表面：青黑 `#0E2427`、深蓝 `#121D31`、幽紫 `#211C35`。
- 孔雀反射：低饱和青绿 `#5CAE9C`、蓝灰 `#5A99B8`、紫灰 `#8966B5`。
- 香槟金：`#C8A75C`，只承担焦点和重要状态。
- 正文暖白：`#EEECE5`；辅助文字不得通过过低字号和过低对比度制造“精致感”。

## 3. 全站 Midnight 主题

### 3.1 主题入口与作用域

主题选择器继续使用现有 `midnight` 标识和 `Midnight` 名称，不新增第二个重复黑色主题。用户在普通页面主动选择 Midnight 时继续持久化；进入 `/pulse` 时继续临时启用 Midnight，离开后恢复进入前的主题。

Midnight 必须是一套完整的全站主题变量，覆盖：

- 页面背景和星光层。
- 导航、搜索、主题面板和移动菜单。
- 四级文字、链接、边界、输入框、按钮、浮层、成功与警告状态。
- 普通内容卡片、公告、列表和分页等通用表面。

不得通过给所有背景简单换成同一个黑色完成主题改造。

### 3.2 星光背景

全站 Midnight 背景使用三层深空材质：

1. 深蓝黑至青黑的低对比度空间渐变。
2. 疏密不同的冷白星光纹理。
3. 极少量香槟金恒星和低透明度蓝绿、幽紫星云。

星光由 CSS 径向渐变和伪元素生成，不增加大尺寸背景图片。星光不能覆盖文字或形成持续高亮闪烁；`prefers-reduced-motion` 下保持静态。

### 3.3 初版标题栏复用

标题栏必须复用现有 `TopNav` 的 DOM、顺序、响应式断点和对齐方式，不创建脉冲页专用标题栏，也不重新调整 Logo、主导航或操作区的位置。

保留初版标题栏的完整结构：

- AlgoWiki Logo 与字标。
- 首页、竞赛 wiki、赛事专区、动态、贡献榜和文档。
- 今日完成/今日脉冲入口。
- 全站搜索框和搜索按钮。
- `Midnight` 主题入口。
- 登录或已登录用户操作区。

本次只改变 Midnight 下的材质和颜色：黑珍珠暗面、孔雀反光、香槟金搜索按钮、细光谱底线。其他主题的标题栏布局和配色不得回归。

## 4. 午夜脉冲页面

### 4.1 页面结构

继续保留真实业务页面的页签和三栏工作区，不恢复已经删除的大型 Hero、演示标题、顶部统计条或 Demo 注释。

以下预览说明元素不得进入产品代码：

- `MIDNIGHT PULSE · DAILY PLANET RULE`。
- 「今天只出现一颗星球」。
- 星球上方的字母、名称、日期。
- 「明日 00:00 自动切换」提示。
- 中央重复的 `2/3 ALGO PULSE` 读数。
- 右下角 `A → B → C` 规则说明。

页面进度继续由现有顶栏脉冲入口和真实模块状态表达。

### 4.2 模块渐变框

问答、挑战、投票和个人轨道继续是独立模块，但不再使用相同的纯黑卡片。每个模块采用低对比度双层渐变：第一层是内部表面，第二层是 1px 渐变边缘。

- 问答：青黑至深海绿，表达知识核心。
- 挑战：深蓝至幽紫，表达训练轨道。
- 投票：青绿、蓝灰和紫灰横向过渡，表达观点纹理。
- 个人轨道：青黑至靛紫，香槟金只出现在标题或进度起点。

卡片保持初版较大的圆角和克制的内部高光。渐变不能降低正文对比度，不能使用高饱和霓虹，也不能在 hover 时大幅改变布局。

### 4.3 字体可读性

桌面端核心正文不得小于 `14px`，导航和页签不得小于 `13px`，模块标签不得小于 `12px`，核心标题不得小于 `24px`。更宽桌面下正文可提升至 `15–16px`，标题最高约 `34px`。

辅助英文不承担关键含义。必须满足足够对比度，不得再次使用 6–9px 的说明文字。

## 5. 每日拟真星球

### 5.1 三颗星球

使用本轮生成的三张独立原创素材：

- A「鎏金风暴」：具有真实云带和涡旋的气态巨行星。
- B「黑曜熔金」：黑曜岩质地表与少量金色地壳裂隙。
- C「极光深海」：深色海洋、风暴云系和克制极光。

素材在正式实现时保存到项目资产目录并转换为 WebP，保留原始 PNG 作为设计源文件或不纳入运行包。页面只请求当天使用的一个 WebP，不能一次加载三张大图。

### 5.2 每日轮换规则

同一天只展示一颗星球，不提供 A/B/C 播放控件，不在同一次访问中自动轮播。

轮换以服务端返回的北京时间业务日期为准，按 A → B → C 循环。固定锚点为：

- `2026-07-20` 为 A。
- `2026-07-21` 为 B。
- `2026-07-22` 为 C。
- `2026-07-19` 因而为 C，下一日回到 A。

同一天刷新、退出再进入或更换浏览器时结果相同。页面在北京时间 00:00 刷新当日 Pulse 数据后才切换星球；浏览器休眠后恢复时必须重新比较业务日期。

轮换逻辑抽为无副作用纯函数，输入 `YYYY-MM-DD`，输出 `A | B | C`，并提供单元测试。

### 5.3 星球展示

生成素材自带近黑方形背景，产品中使用圆形裁切容器和每张图单独校准的缩放/焦点变量，使星球球面填满圆形容器并完全消除黑色方框。不得通过把黑色像素全局变透明的方式处理，因为这会破坏黑曜星球和星球背光暗部。

星球保持完整球体、柔和环境光和现有轨道线。只允许非常轻微的 6–8 秒浮动；完成动作可以触发一次短促光晕响应。减少动态效果时取消浮动和位移。

## 6. 响应式与性能

- 2048×1080、1920×1080、1440×900、1366×768 和 1280×720 下，导航与核心工作区不产生页面滚动条，也不裁切真实交互控件。
- 标题栏使用现有响应式断点；移动端继续使用现有菜单，不把桌面搜索框强行缩小塞入屏幕。
- 移动端按星球、问答、挑战、投票和个人轨道自然纵向滚动，不产生横向溢出。
- 三张 WebP 单张目标体积不高于约 500 KB；只加载当天星球。
- 星光与渐变优先使用 CSS，不引入 WebGL、Three.js 或新的动画依赖。

## 7. 实现边界

- 不修改午夜脉冲后端业务模型和 API 契约，星球选择使用 `GET /api/pulse/today/` 已返回的业务日期。
- 不改变 `TopNav` 的结构、路由和事件逻辑，只扩展 Midnight 主题视觉。
- 不新增字体和第三方 UI/动画依赖。
- 不把 `.superpowers/` 预览文件、浏览器截图或临时静态服务脚本提交到产品代码。
- 不推送、不部署、不合并到正式分支。

## 8. 验证标准

### 8.1 自动化测试

- 主题测试覆盖 Midnight 变量、临时进入、退出恢复和其他主题不受影响。
- 星球选择纯函数覆盖锚点日前、锚点日、连续三天、跨月、跨年和无效日期回退。
- 页面测试确认同一时刻只渲染一张星球图片，不存在轮播或暂停控件。
- 页面使用 API 业务日期而不是浏览器本地日期。
- 00:00 数据刷新和页面重新可见时会更新星球；同一业务日期不重复切换。
- 已有问答、挑战、投票、绑定、积分和主题恢复测试继续通过。

### 8.2 构建与浏览器验收

- 前端相关测试、后端 Pulse 测试、迁移检查和生产构建通过。
- 桌面视口逐一验证标题栏与初版对齐、模块渐变、星光背景、单星球、无黑框和无滚动条。
- 移动视口验证自然滚动、无横向溢出、文字可读和触控区域不退化。
- 控制台无错误或新增警告；星球资源只请求当天一张。
- `prefers-reduced-motion` 下无持续位移或闪烁。
